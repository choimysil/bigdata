전자정부 DevStudio 확장프로그램 설계도
버전: 2.0 / 작성일: 2026-11-04
대상: VS Code 및 호환 Cursor 버전 / 오프라인·폐쇄망 우선

1. 제품 정의
전자정부 DevStudio는 표준 개발 매뉴얼을 중심으로 현재 프로젝트를 분석하고, 개발 목적에 맞는 파일과 수정 위치를 찾아 단계별 작업을 안내하며, 검증된 템플릿으로 실제 소스코드를 생성·수정·검증하는 VS Code 확장프로그램이다.
핵심 차별점은 '검색'이 아니라 '매뉴얼 기반 개발 작업 실행'이다.

2. 개발 목표와 범위
- 1차: Spring Boot/eGovFrame 5.x, Maven, Java, MyBatis, Thymeleaf, MariaDB/MySQL
- 2차: PHP/Laravel, Python/FastAPI
- 3차: Next.js, Vue, Flutter 등 어댑터 확장
- 네트워크와 외부 AI API 없이 기본 기능 작동
- 실제 프로젝트에 대한 자동 변경은 사전 미리보기 및 사용자 승인 필수
- 지원하지 않는 프로젝트 구조는 자동 변경하지 않고 수동 안내로 전환

3. 사용자와 핵심 사용 사례
- 신입 개발자: 낯선 프로젝트 구조 파악, CRUD·검색·페이징 개발
- 실무 개발자: 반복 코드 생성, 기존 기능 변경, 오류 진단
- 강사/교육기관: 표준 절차 실습, 단계별 검증
- 조직 관리자: 회사별 매뉴얼·템플릿 배포 및 표준화

4. 주요 화면 구성
A. 왼쪽 Activity Bar: ???? 아이콘
B. 왼쪽 TreeView: 매뉴얼 목차, 프로젝트 분석, 작업 기록
C. 가운데 Webview 탭: 단계별 매뉴얼, 코드 예제, 진행률, 생성 옵션
D. 가운데 기존 편집기: 실제 소스 파일 및 변경 비교(Diff)
E. 하단: VS Code Terminal/Problems/Output을 통한 빌드·검증
F. 보조 사이드바: 선택적 분석 정보(사용자 레이아웃에 따라 표시)

화면 예시
[왼쪽 ????]       [가운데 매뉴얼/코드 탭]           [하단]
- 프로젝트 분석       작업 목적 / 사전 조건             Maven 빌드
- 표준 매뉴얼         STEP 1~5 / 관련 파일              테스트 결과
- CRUD 생성          코드 예제 / 변경 미리보기          오류 메시지
- 작업 기록          적용 / 다음 단계

5. 핵심 기능
5.1 프로젝트 자동 분석
- pom.xml, application.yml/properties, Java 패키지, 컨트롤러, 서비스, 매퍼 XML, 템플릿 탐색
- URL 매핑, 클래스·메서드, 의존 관계, SQL statement ID 인덱싱
- Controller -> Service -> Mapper -> SQL -> View 연결 정보 제공
- 정적 분석 결과는 확실/추정/미확인 상태로 구분
- 동적 라우팅·리플렉션·런타임 SQL은 완전 추적을 보장하지 않음

5.2 표준 개발 매뉴얼
- 매뉴얼 검색 및 목차, 단계별 읽기, 관련 파일 열기, 진행 상태
- 모든 매뉴얼은 동일한 7개 항목 사용:
  (1) 작업 목적 (2) 사전 조건 (3) 처리 흐름 (4) 수정 대상
  (5) 단계별 절차 (6) 코드 예제 (7) 검증/완료 기준
- 작업 단계별 파일 역할, 찾는 규칙, 변경 지점, 예상 결과 제공
- 초보자용 설명과 실무자용 간략 보기 모드
- 코드 문법 강조, 복사, 주의사항, 오류 해결 링크, 이전/다음
- 프로젝트/프레임워크 버전별 매뉴얼 적용 범위 표시

5.3 소스코드 생성
- DB 테이블과 프로젝트 구조를 기준으로 VO/DTO, Controller, Service, ServiceImpl, Mapper, SQL, Thymeleaf HTML 생성
- 프로젝트 기존 패키지/명명 규칙과 맞지 않으면 사용자에게 선택 요청
- 중복 파일, URL, 메서드, Mapper ID, Bean 이름 검사
- 생성 전 파일 목록과 변경 내역 미리보기

5.4 기존 소스코드 수정
- 단순 문자열 치환이 아니라 JavaParser/AST 및 XML 파서를 우선 사용
- 정확한 클래스/메서드/노드를 식별한 뒤 수정안 생성
- VS Code WorkspaceEdit 적용, vscode.diff 비교, 사용자 승인
- 불확실하거나 충돌 가능성이 있으면 자동 적용 금지
- 저장 전 백업 또는 Git 변경 이력 확인 및 되돌리기 지원

5.5 빌드·검증
- Maven 빌드/테스트를 VS Code Task 또는 Terminal로 실행
- 출력 로그에서 대표 오류 패턴 탐지, 사전 등록된 해결 매뉴얼 연결
- 빌드 성공만으로 기능 정상 작동을 단정하지 않음
- HTTP/DB/화면 동작은 별도 통합 테스트 또는 수동 검증 단계 제공

6. 표준 매뉴얼 분류
01 프로젝트 구조 및 설정
02 Java/Spring 기본 개념과 어노테이션
03 Controller/Service/Mapper 호출 흐름
04 DB 연결 및 MyBatis
05 CRUD: 목록/상세/등록/수정/삭제
06 검색/정렬/페이징
07 입력 검증/예외 처리
08 파일 업로드/다운로드
09 로그인/세션/권한/CSRF
10 트랜잭션/로그/테스트
11 빌드/배포/운영
12 오류 해결 사전
13 회사별 사용자 매뉴얼

7. 매뉴얼 데이터 구조
- manuals/<framework>/<version>/<topic>/manual.md : 사용자에게 보이는 설명
- manuals/<framework>/<version>/<topic>/workflow.yaml : 단계, 조건, 대상 파일, 검증 규칙
- templates/<framework>/<version>/<topic>/* : 생성 코드 템플릿
- adapters/<framework> : 파일 인식·구문 분석·코드 적용 모듈
- schemas/ : 매뉴얼과 워크플로 유효성 검증 스키마
- manifest.json : 패키지 버전·호환성·해시

workflow.yaml 개념 예시:
id: egov-sample-search
framework: egovframe-springboot
versionRange: '5.x'
title: 샘플 목록 검색 기능 추가
steps:
  - id: controller
    title: Controller 확인
    targetRole: controller
    action: locate-and-review
    verify: mapping-exists
  - id: service
    title: Service 검색조건 전달
    targetRole: service
    action: propose-edit
    verify: signature-consistent
  - id: mapper
    title: Mapper 검색 SQL
    targetRole: mapper
    action: propose-edit
    verify: statement-id-and-parameters
  - id: view
    title: 검색 폼 수정
    targetRole: view
    action: propose-edit
    verify: form-parameter-matches
  - id: test
    title: 빌드 및 기능 검증
    action: run-checks
    verify: build-and-manual-test

8. 매뉴얼 처리 엔진
(1) 사용자가 개발 목적 선택
(2) 현재 워크스페이스/프레임워크/버전 판별
(3) 해당 매뉴얼과 적용 조건 확인
(4) 파일·심볼·SQL 인덱스에서 대상 매칭
(5) 일치 결과와 신뢰도 및 미확인 항목 표시
(6) 단계별 안내 및 코드 변경안 생성
(7) Diff 미리보기 -> 사용자 승인
(8) 실제 파일 생성/수정
(9) 빌드/테스트/수동 검증
(10) 작업 결과와 로그 저장

9. 코드 생성 및 수정의 안전 원칙
- 워크스페이스가 신뢰되지 않으면 쓰기·명령 실행 제한
- 파일 경로가 워크스페이스 밖을 가리키면 차단
- 기존 파일 덮어쓰기 금지(명시적 승인 예외)
- 파일 인코딩, 개행, 포맷, import 규칙 보존
- 중복 생성 방지와 재실행 시 멱등성 확보
- 수정 전 파일 스냅샷/해시 확인으로 동시 변경 충돌 감지
- 파일 여러 개 변경 시 사전 검증 후 일괄 적용 및 복구 절차
- SQL 생성 시 파라미터 바인딩 사용, 위험한 문자열 결합 지양
- 로그인/보안 관련 템플릿은 별도 보안 검토

10. 기술 아키텍처
확장 UI: TypeScript + VS Code Extension API + TreeView + Webview
매뉴얼: Markdown + YAML + JSON Schema
프로젝트 분석: JavaParser(로컬 Java 프로세스 또는 번들 도구), XML parser, 설정 파서
코드 생성: 버전별 템플릿 엔진
파일 변경: WorkspaceEdit, workspace.fs, vscode.diff
검증: Tasks/Terminal, Maven, JUnit
로컬 데이터: JSON/SQLite(필요 시) - 프로젝트 인덱스, 작업 상태
폐쇄망 배포: .vsix 및 필요한 실행 구성요소 사전 패키징

12. 언어별 어댑터 인터페이스
- detectProject(): 프레임워크/버전 판별
- indexWorkspace(): 프로젝트 구조 인덱싱
- resolveTarget(role, context): 역할별 파일·심볼 탐색
- planChanges(workflow, context): 수정안 생성
- validateChanges(plan): 충돌/구문/연결 검증
- applyChanges(plan): 승인된 변경 적용
- runChecks(): 빌드·테스트 수행
공통 UI와 매뉴얼 엔진은 재사용하고 분석·생성 로직은 언어별 구현.

13. 첫 번째 검증 시나리오
대상: 실제 eGovFrame Spring Boot 샘플 프로젝트
작업: SAMPLE 테이블의 목록 검색 기능 추가
- SAMPLE(ID, NAME, DESCRIPTION, USE_YN, REG_USER) 구조 확인
- 관련 Controller/Service/Mapper/HTML 파일 찾아 연결
- 검색 조건과 파라미터 일치 여부 검증
- 변경 파일 및 Diff 표시
- 승인 후 코드 적용
- mvn clean package 실행
- 검색 전/후 목록 기능 확인
성공 기준: 잘못된 파일 수정 없이 반복 수행 가능하고, 실패 시 원복 가능할 것.

14. 단계별 개발 계획
P0. 기술 검증: VSIX 설치, Webview, 현재 프로젝트 파일 열기, 단일 파일 편집
P1. 표준 매뉴얼: 목차/검색/단계 UI, Markdown+YAML 로딩, 완료 상태
P2. 프로젝트 분석: Controller/Service/Mapper/SQL 관계 인덱싱
P3. CRUD 생성: 신규 파일 생성, 충돌 검사, Diff, 승인
P4. 기존 코드 수정: AST 기반 위치 탐색, 다중 파일 변경, 복구
P5. 빌드·검증: Maven/JUnit 및 오류 사전 연결
P6. 언어 확장: PHP/FastAPI 어댑터
각 단계는 실제 프로젝트 회귀 테스트를 통과한 뒤 다음 단계로 진행.

15. 검증 및 품질 기준
- 매뉴얼 스키마 검사 및 문서 누락 검사
- 코드 템플릿 단위 테스트와 생성 결과 컴파일 검사
- 파일 수정 전후 Diff 스냅샷 테스트
- 프로젝트 구조별 샘플 fixture 테스트
- 중복 실행/실패/취소/되돌리기 테스트
- Windows 우선 검증, macOS/Linux는 별도 호환성 시험
- Cursor는 VS Code와 버전 차이가 있으므로 별도 설치·API 테스트

16. 배포·운영·비용
- 개발자 개인용 .vsix 제작 및 수동 설치 가능
- 마켓 등록 없이도 배포 가능하나 조직별 보안 승인 필요
- 기본 기능은 외부 AI 사용료/클라우드 서버 운영비 없이 설계 가능
- 개발·테스트 인건비, 매뉴얼 유지보수, 번들 의존성 라이선스 검토는 필요
- Java/Maven/DB 실행 환경은 사용자의 프로젝트 요구에 따라 별도 필요

17. 구현 시 주의사항
- eGovFrame 버전별 패키지 구조·보안 설정·템플릿 차이를 단일 규칙으로 가정하지 않음
- 코드 자동 수정의 정확도를 100% 보장하지 않음
- 기존 프로젝트 분석 결과가 불완전하면 해당 단계를 수동 처리로 전환
- 실제 실행 검증과 보안 점검을 통과하지 않은 코드를 자동 배포하지 않음
- 매뉴얼은 프로그램 UI와 분리하여 업데이트 및 회사별 확장 가능하게 설계

18. 최종 제품 방향
'찾아주는 검색기'가 아니라 '표준 절차를 따라 실제 프로젝트를 안전하게 변경하는 개발 작업 도우미'.
첫 출시의 우선순위는 eGovFrame 한 프로젝트에서 매뉴얼 -> 파일 연결 -> 코드 변경 미리보기 -> 승인 적용 -> 검증까지 완주하는 것이다.
